# `swarm.sh status` lists stacked builds whose parent moved or merged, and both conductor modes tell the child to merge it in

Waits on drop-unused-switches (conduct_story_mode) and backlog-conductor (conduct_backlog_mode). status_report (bin/swarm.sh:3945-4005) gains a Stacked section, printed outside herdr too. It looks at each story that is ready or blocked, has a worktree, and has a `stacked <slug>` event naming its parents (stacked-start-and-merge-order logs it), and prints one line per parent that needs action: `<child>: merge origin/story/<p>` when p's PR is open and its head is not in the child's branch (git merge-base --is-ancestor, after a fetch); `<child>: merge origin/<base> (<p> merged)` when p's file is gone or its PR merged and the base's head is not in the child's branch, so after a squash merge the child takes main; `<child>: lost story/<p>` when p's PR closed unmerged, or its branch is gone while p is on the board. A line ends `(no builder)` when the child's builder is not open. With no such line, there is no section. Add stacked_rule and put it in both conduct_story_mode (:2562-2582) and conduct_backlog_mode. After each `swarm.sh wait` or `watch` returns, and after a builder opens a PR, the conductor runs `swarm.sh unblock`, starts what it readies (a ready story whose worktree exists has started: never run story for it), then runs `swarm.sh status`. For each merge line it sends `swarm.sh tell <child> findings <file>`, the file saying to merge that ref, re-run the tests and push. For a `(no builder)` line it first starts one in the child's worktree with `swarm.sh agent <tab> <child> <worktree> <the role swarm.sh _role <child> prints> <brief>`, the brief saying the same and to reply with the PR URL. Any review of the child from before that merge is stale: it reviews the new head. For a lost line on a ready child it runs `swarm.sh close <child> paused`, which holds the child for the lead; a lost line on a held (blocked) child goes in its report.
