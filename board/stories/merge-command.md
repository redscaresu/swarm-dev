# `swarm.sh merge [--board] [--head <sha>] <pr-url>` merges a green PR with its head pinned, waits for main's CI, logs each step and reconciles

New dispatch arm and merge_pr. Parse owner/repo/number from the URL; refuse anything else. Refuse when HERDR_PANE_ID is one of this project's panes (own_panes, bin/swarm.sh:486), unless merge = agent and herdr names a live conduct-* agent there: start_agent's guard blocks only `gh pr merge` (:649-651), so without this any builder could merge through swarm.sh. Read state (OPEN only) and headRefOid; with --head, refuse unless the head is that SHA (the conductor passes the SHA it reviewed). Unless --board, find the story or epic whose prs: lists the URL (board stories; board epics, as reconcile does at :2445-2463) and refuse unless it is in review. One helper reads `gh api repos/<o>/<r>/commits/<sha>/check-runs?per_page=100` and passes only when there is at least one run, all completed, each success, skipped or neutral (the block-red-pr-merge hook's rule, ~/.claude/hooks/block-red-pr-merge.sh:45-70, which never sees a gh call made inside swarm.sh); refuse naming each failing or pending check. Method from `gh repo view --json squashMergeAllowed,mergeCommitAllowed,rebaseMergeAllowed`: squash, else merge, else rebase. Run `gh pr merge <number> --repo <o>/<r> --<method> --match-head-commit <sha>`, plus --admin only with new key merge_admin = true (default false; CONFIG_KEYS, load_config, method table row, config_test), never --auto. Log `merge <target> ok`. Read the PR's mergeCommit oid and poll the same helper on it until it passes, a check fails, or 30 minutes (SWARM_MERGE_CI_SECONDS and SWARM_MERGE_POLL override for tests); log `main-ci <target> ok`, `red <check> <url>` or `timeout`. Unless --board, then run reconcile (one code path; it closes the builder, clears the build, pulls and finishes), also when main was red, since the PR has merged. Exit non-zero on red or timeout, naming the check. Target is the slug, or the URL with --board. main() logs a failure with its die line; on success the step lines are merge's own, with no second merge line. Docs: usage header, README command table and the 'PR waiting for you' row, method.md § Merging, config table and events.tsv paragraph.
