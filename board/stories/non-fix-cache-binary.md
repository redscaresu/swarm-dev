# The patch gate's non-fix cache reads and writes through the binary, with the same key and files

Needs Get, Put and Path from go-gh-cache-files; register from go-entries-per-file; non_fix_cache's row in docs/port/copies.tsv from shared-copies-list; and shared-gh-cache-call's You: steps (the gh_cache reading, and the user clearing this story on the board PR). The carve-out story: it swaps the call in non_fix_cache (bin/lib/board.sh:1781-1801), a release-gate file, and changes no rule, so P12 does not apply. The _non-fix-cache entry takes get or put, rule, repo, board rel, from and to, with SWARM_GH_CACHE and SWARM_GH_FRESH as gh_cache.py takes them. The name is non-fix/rule<rule>-<board>-<from>-<to>, with every byte of rel but a-z, 0-9, ., _ and - as %XX. That is rel's bytes as bash passes them under a UTF-8 locale, which the differential run passes on (LC_ALL, tests/diff_run.sh:171). Under a non-UTF-8 locale on Linux the Python encodes rel through the locale first (board.sh:1789), so old and new name such a rel two ways, and the new one only misses the cache. get prints a cached JSON string, the empty string included, and fails for none, for a non-string and under SWARM_GH_FRESH. put writes stdin minus its last character. non_fix_cache runs binary_run in a subshell of its own. binary_run dies outside its own subshell when there is no binary (bin/lib/binary.sh:264), and the put at board.sh:1735 is in no $(...), so a bare call would end non_fix_change before it prints its answer (:1736). In the subshell, a missing binary or a failed build fails the cache as a failed python3 does today. It still fails at once, starting no process, with no GH_CACHE and on a get under SWARM_GH_FRESH (:1782-1783), and keeps `2>/dev/null`. The name rule sits in internal/ghcache, outside the protected packages.
