# swarm-dev 0.28

"0.28" names this design. It ships as four releases, v0.28.0 to v0.31.0 (Rollout § Stages).

## Problem

0.27 shipped on 2026-10-25 with the retro's design questions unanswered and its biggest feature
pulled. The 0.26 and 0.27 retros (`board/epics/retro-and-shared-rules.md`, Appendix) left eight
things the swarm cannot settle for itself:

1. **A release needs no retro.** `merge --release` checks docs against `bin/`, `commands/` and
   `hooks/` and nothing else. The retro before 0.27 happened because the user asked for it.
2. **The outer loop does not close.** 395 findings were declined out-of-scope between v0.25.0
   and 2026-10-25 (about 100 of them in the v0.25.0 to v0.26.0 window the 0.26 retro counted);
   75 finding kinds were fixed on 3 or more PRs over all time (the 0.26 retro counted 40 in its
   window), and no list says which of them has a check, because no such list exists; the lead's
   memory holds about 40 rules the swarm cannot read. `.swarm/checks-filed.tsv` does not exist,
   so no `checks:` story was ever filed from the recurring block.
3. **A builder's full local suite takes about 18 minutes when nothing else runs.** From
   `.swarm/test-runs.tsv` (35 completed full runs, 2026-10-24/25): median 1050 s and p90 1391 s
   with no other run going, 1757 s median with one other, 3405 s with seven others. CI's sharded
   run takes about 3.8 minutes. Contention doubles the time; the suite alone is still 18 minutes,
   and every review round runs it locally, then CI runs it again on the same head.
4. **One conductor serialises review.** On 2026-10-24 one backlog conductor carried seven green
   PRs one at a time. conductor-lanes (#480, 6caca7f) and conductor-lanes-start (#482, a228cab)
   were built for 0.27 and drew multi-lane gaps in each of five review rounds on fable: stranded
   stories, no one ending the epic, lane tabs left open, notes and watches folded wrongly, lane
   reservations racing a failed start, lane metrics merged. Pulled from 0.27 on 2026-10-25 as
   draft PRs with their branches kept.
5. **The ladder threshold was set by feel.** `step_up_findings` is 3. The user asked for 2 on
   2026-10-25 and left it for this HLD. The data to decide it is thin: `.swarm/findings.tsv`
   carries a round number on 7 of 5177 rows (`--round` arrived on 2026-10-24), and the
   `findings-3` trigger has fired twice, both on the conductor-lanes PRs above.
6. **Whole-file `touches` hold stories that do not clash.** At least four false clash holds on
   2026-10-24; touches-clash was logged on #428 (twice, declined) and #480. A story that names a
   bare file clashes with every story that names any symbol in it.
7. **Failures that reach nobody.** A step-up that failed partway left findings-told-sent 3.5
   hours with no builder; a brief sat unsent in a pane's input box for 3h42m; `wait --stall`
   read a long `make test` under load as a stall. Each was found by the user, not by swarm.sh.
8. **A night on the top rung is expensive.** #480's four rounds at xhigh used about 6% of the
   week's usage and moved fable from 20% to 35% of its own limit. Nothing in the ladder or
   `top_rung_rounds` weighs that.

Behind all eight: the swarm finds these things and the user has to notice them. The retro is
the one place they surface, and it is not part of the release.

## Goals

What must be true when 0.28 ships, each checkable. 0.28 ships in stages (Rollout § Stages); each
goal belongs to one stage.

1. **No release without a retro.** `merge --release` refuses a bump with no retro file marked
   done for that version, and `next` prints the retro before `release`. This ships in the last
   stage (v0.31.0); the stages before it release without a retro, and the last stage's retro covers them
   all.
2. **The outer loop closes at the retro.** `swarm.sh retro` lists out-of-scope findings with no
   story, recurring kinds with no check, incidents, reaped load and unplaced memories; each item
   in the 0.28 retro file ends as a story, a check, a rule or a reasoned drop. Last stage, with
   Goal 1.
3. **Generic rules reach every agent.** A rules file ships in the plugin, the builder brief and
   the review brief both carry its text (a test fails when either drops it), and it holds
   Appendix B's generic engineering rules.
4. **A builder's local test run has p90 under 5 minutes**, read from `flow`'s `test_runs`, which
   must first learn to count partial runs (today it keeps only runs labelled `all`,
   bin/lib/flow_test_runs.py:28); codex runs no tests, checked by no test process left with
   PPID 1 after a review; and a machine-wide suite cap exists as a setting, off by default.
5. **PRs are reviewed in parallel.** Each review agent carries its PR from green CI to merge or
   to the user; the conductor carries none. No green PR waits on another PR's review.
6. **This board runs `step_up_findings = 2`** (the plugin default stays 3), and `flow`'s `cost`
   shows tokens per ladder rung and per
   step-up.
7. **No false clash holds from a bare file.** The clash check compares parts, /plan-epic writes
   `file:part`, and backlog stories are checked like epic stories.
8. **No story sits unworked unseen.** A ready, building or in-review story with no live agent
   of any role working on it and no tell pending reaches the lead through `wait --lead`, `next`
   and `status`, including a failed step-up and an unsent brief; a running suite is never read as
   a stall. Checked by `flow`'s `lead_queue`: minutes from the first event with no live agent to
   the `lead-woken` line, and no alert that fires between review rounds on a PR whose builder is
   working.
9. **Less work and noise per story** (Design § Less work, less noise): board-only PRs skip
   codex; no incident for a wait on a busy agent; no nudge to a working agent; one helper each
   for the board-root path, the PR contents reader and the name cut; docs updated in the same
   story as behaviour; reconcile finishes merged stories the pull already removed. The rule that
   nothing a board sets is removed unchecked (Design § Removing what a board sets) is a line in
   AGENTS.md and a **Done when** on each removal story, not a goal: 0.28 removes nothing.
10. **The `later` stories ship or are dropped with a reason**: slow-test-files, epic-guard-gaps,
    plan-hld-gaps, small-fixes-027, handover-and-usage, dash-grant-queue, ci-three-minutes.

## Non-goals

- **Conductor lanes.** Several conductors per epic are dropped, with their draft PRs, branches
  and three stories (Design § Review in parallel).
- **Changing how the top rung runs.** Fable stays at `xhigh` with `top_rung_rounds` 2; 0.28 only
  measures it.
- **A usage gate on the ladder.** It needs a usage reading swarm-dev does not have.
- **Running swarm-dev's own swarm from main.** Fixes reach it through patch releases instead.
- **A guard on hand-written polling loops.** Briefs cover it.
- **Real cloud, infrafactory or any project other than swarm-dev.** 0.28 changes swarm-dev only.
  A swarm-dev change still reaches every board that runs the plugin on `claude plugin update`:
  a removal is checked against every board the user runs (Design § Removing what a board sets),
  and each stage's release PR lists the behaviour changes every project gets (review agents
  merging, the clash rule, the rules file, a ladder default) and names the infrafactory build
  they were tried on, or says none was.

## Design

Each part records a decision the user made in the co-writing, on the date given. The evidence
behind each is in the appendices; the plan is drawn from this section.

### The retro gate: no release without a retro (decided 2026-10-25)

The retro becomes the outer loop's fixed point. Collect, out-of-scope triage and the memory sort
all happen there, so none depends on a conductor finishing (`collect` has never run: Current
state).

- **`swarm.sh retro --since <tag>` writes the report** for everything since that tag (the last
  `v<version>` tag by default; the v0.31.0 retro runs with `--since v0.27.2`, so the three
  stages before it are inside its window):
  declined out-of-scope findings with no story; recurring kinds with no check (the old collect
  step, with Appendix A's kind names folded first); red mains, flaky tests, stalls and other
  incidents; leftover load the swarm had to reap; and the lead's memories not yet placed (see
  Memory extraction). It reads `.swarm/` and the board, and keeps to the gh budget rule in
  Appendix C.
- **The retro is a `kind: lead` story**, `retro-<version>`, with **You:** steps, as the method
  requires of any step that needs the user (AGENTS.md: a question for the user is a `kind: lead`
  story). The lead opens it when `next` names the retro, picking the version then (minor or
  patch, from what has merged since the tag), and `swarm.sh retro` writes its report into the
  story. A `kind: lead` story is what hooks/lead-stop.sh already lets the lead stop on, so the
  lead's turn is not held on a step only the user can finish.
- **The user and the lead go through it.** Each item ends as a story, a check, a rule (rules
  file, a project's brief or AGENTS.md), or dropped with a reason.
- **The result is a retro file on the board** for the version being released, with the window
  it covered (`covers: v0.27.2..v0.31.0`), merged by a board PR like any other. It records each
  item and what became of it; the story is done when the file is on `main`.
- **`merge --release` refuses a minor bump** unless a retro file whose window starts at or before
  the last tag is on `main` and marked done. The first retro's window starts at v0.27.2, before
  v0.30.0, so it passes. A patch (fixes only, as the release arm already defines it)
  needs no retro, so the patch cadence in Design § Less work stands, and the next retro's window
  covers the patches. The existing docs gate stays beside it.
- **`next` prints the retro** as the step before `release` when `main` has a change since the
  last tag that is not a fix and no retro file's window starts at that tag.

### Nothing sits unworked unseen (decided 2026-10-25)

- **The rule:** a story that is ready, building or in review with no live agent of any role
  working on it, and no tell pending, reaches the lead. `wait --lead` returns on it, and `next`
  and `status` name it first. "Of any role" matters: between review rounds the review agent is
  closed while the builder fixes (`.swarm/events.tsv`, 2026-10-25: `close
  review-config-keys-back` at 11:30:35, #493 merged 11:33), and that state is not an alert. The
  rule is tested against it. It covers cases not yet seen, not only the four below; the measure
  is `flow`'s `lead_queue` minutes (Goal 8).
- **Every alert names its exit.** A failed step-up: `step-up --resume <slug>`. An unsent brief
  still unsent after one resend: `swarm.sh close <slug>` then `resume`. A review agent that
  never started: `swarm.sh review-agent <slug> <pr>` again, or the fallback reviewer. A story
  with no live agent of any kind: `resume`, or `hold` with a reason. `next` prints the exit
  beside the line.
- **A step-up that fails partway** (its `.swarm/briefs/*.step-up` marker left behind) wakes the
  lead at once, not in the conductor's final report. In 0.27 findings-told-sent sat 3.5 hours
  with no builder.
- **An unsent brief.** After a start or a tell, a pane that is idle with the brief still in its
  input box (herdr shows `[Pasted text #N]`) gets the brief sent once more; if it is still
  unsent, it reaches the lead. In 0.27 one sat 3h42m.
- **A long test run is not a stall.** The stall check counts a suite running in the agent's
  worktree as work. A mark today is an empty file named by PID and the log line carries the
  branch, not the worktree (scripts/test.sh:161), so the plan chooses a PID-to-cwd lookup or a
  richer mark.
- **A review agent that never started.** A PR in review whose review agent failed to start,
  with no round under way, reaches the lead the same way, instead of the conductor reviewing
  alone. In 0.27.1 both story PRs went through with codex only and nobody was told.
- **Signals must be true.** The false "not taken up" (about 29 in 0.27, fixed by #464) taught
  everyone to ignore the one real case. Any new alert here is tested against the false case as
  well as the real one.

### Memory extraction (decided 2026-10-25)

Rules the lead learns from the user leave the lead's private memory and land where every agent,
on every project, works under them.

- **A rules file in the plugin.** Generic engineering rules live in one file shipped with
  swarm-dev, which builders and review agents both read on every project: builders before they
  write, reviewers as a checklist against the diff. It reaches briefs through `project_rules`
  (Current state), as a plugin-level source appended before the project's brief and `lesson:`
  markers: one mechanism, not a second. A project gets new rules when it upgrades the plugin.
  The first contents are Appendix B's "generic engineering rules", each with its one-line why.
- **Checks over prose.** A rule that can be checked becomes a guard, a test or a `next` step
  instead of a line in the rules file. Appendix B's "should be swarm-dev behaviour" list is that
  set for 0.28.
- **The retro sorts each new memory.** The retro (topic 1) lists the lead's memories not yet
  placed, read from the main checkout's directory under `~/.claude/projects/` on the machine
  the retro runs on (Current state names the store; a `--memory <dir>` names another), and the
  user sorts each into: a check, the rules file, one project only (its
  `.claude/swarm/brief.md` or AGENTS.md), or drop. The swarm never promotes a rule on its own.
  Once a rule is placed, the lead's memory of it is deleted, so memory holds only what is not
  yet placed.
- **Appendix B's sort stands as written** (agreed 2026-10-25). Appendix C's swarm-dev rules go
  into this repo's AGENTS.md (development rules) or become 0.28 work where marked.

### Test speed (decided 2026-10-25)

A review round runs the full suite once, in CI. Everything local is small.

- **A builder runs only the tests for what it changed.** Before a push it runs the test files
  that cover the files in its diff; CI's full sharded run is the gate. How a builder finds
  those files (a map from source to test files, or the story's `touches`) is the plan's to
  choose, and the choice must fail toward running more, never fewer: a changed file with no
  known tests runs the full suite.
- **codex reviews the diff and never runs tests.** Today `codex-review` runs `codex exec review`
  with no sandbox flag (bin/swarm.sh:661-700), so what codex may run is codex's own config, and a
  line in the prompt is a request, not a stop. The plan picks a mechanism that is a stop: a codex
  sandbox mode that blocks execution, or `scripts/test.sh` refusing to run under codex's
  environment. Checked by no test process left with PPID 1 after a review (Appendix C). This
  removes the second full run per round, the orphaned SLOW files and part of the codex quota
  pressure (Appendix D: 37 limit hits).
- **The slowest test files get faster** (the story slow-test-files), so CI and anyone running
  the whole suite benefit.
- **A machine-wide cap on concurrent suites, off by default.** A setting caps how many full or
  partial suites run at once on the machine; a run past the cap waits its turn. Today's run
  marks live under each project's own `.swarm/test-runs.d/` (scripts/test.sh:133-137), so a
  run in another project is invisible: the cap needs a machine-wide marks directory, and the
  setting lives where a machine-wide value can (the plan chooses). The default is no cap. It
  exists for a machine where contention comes back, so it is a setting, not a behaviour change.
- **Target:** a builder's local test run has p90 under 5 minutes, read from `flow`'s `test_runs`
  section; CI's median PR time stays near 3 minutes (ci-three-minutes). The cost to watch is
  more red CI runs from tests a builder did not run, read from `flow`'s `ci_health`.

### Review in parallel: the review agent carries its PR to merge (decided 2026-10-25)

One conductor serialised seven green PRs on 2026-10-24 because every PR's review loop ran
through its one session. The per-PR loop moves to the agent that already exists per PR.

- **The review agent owns its PR from green CI to merge.** It reviews, triages its own findings
  (fix, or decline as nit, low value, out of scope or wrong, logged with `log-finding` as now),
  tells the builder, waits for the new head, reviews again, and ends the loop by the same rules
  as today: a round with nothing fixed is a pass; `step_up_findings` and `top_rung_rounds` still
  apply. On a pass it merges with `swarm.sh merge` under `merge = agent` or a `merge` grant, or
  hands the PR to the user with `swarm.sh review` otherwise. Chosen as the simplest option
  (user, 2026-10-25): one agent per PR and no new role.
- **The review agent stops being read-only.** It gains triage, `tell` to its own builder, and
  merge. It never edits code; the builder still does. Two gates change by name: `merge_caller`
  (bin/lib/merge.sh:94-115), which today lets a merge run from a project pane only when it is a
  conductor's under `merge = agent`, opens to `review-` panes as well and still refuses a
  builder's; and the review brief's read-only paragraph (bin/lib/build.sh:760) is rewritten, with
  AGENTS.md and docs/reference.md's "read-only" lines. Every merge still goes through
  `swarm.sh merge`, which pins the head and requires green checks, and the guard still refuses
  any other merge.
- **Its `tell` fires the ladder.** `swarm.sh tell <slug> findings` counts the round and steps the
  builder up or holds the story at the top rung (bin/lib/agents.sh:1610-1620), as the
  conductor's tell does today. A step-up that fails partway reaches the lead through Design §
  Nothing sits unworked unseen, and the review agent tells its conductor.
- **Landing is still a queue, review is not.** N review agents merging share one main checkout:
  `reconcile` takes a lock and waits for another holder (bin/lib/board.sh:1542-1552), and each
  merge waits for CI on main. That queue is seconds at the lock plus one CI run, not a review
  round, which is what Goal 5 measures.
- **The conductor stays one per epic and stops carrying PRs.** It starts builds as stories go
  ready, takes escalations (a step-up that fails, a held story, a review agent that cannot
  finish), and ends the epic when the last PR merges. It no longer waits on any one PR.
  `swarm.sh upgrade` waits for whichever agent owns a PR, not only the conductor.
- **Lanes are dropped.** The draft PRs #480 and #482 are closed and the branches
  story/conductor-lanes and story/conductor-lanes-start deleted; the stories conductor-lanes,
  conductor-lanes-start and conductor-lanes-on leave the board. Lanes split stories between
  conductors, and nearly every gap review found in eight rounds came from that split.
- **The lanes review is this design's checklist.** Its findings that carry over to agents
  working one epic in parallel, which the plan must answer:
  - a story blocked on work no agent will do (a `kind: lead` parent, or a blocked parent with
    no `depends_on`) must not count as waiting on an agent;
  - a reservation taken by a start that then fails must be released and its waiters told;
  - notes queued during reconcile must survive a reconcile that fails under `set -e`;
  - per-agent metrics (`flow`'s `idle_slots`, dash's reported conductors) must not merge
    agents into one key or look for reports by a guessed name;
  - `upgrade` must wait for whichever agent owns a PR, not only the conductor;
  - a derived value (like the lane fold, written out five times in #480) has one source;
  - nobody may be left to end the epic, and no tab may be left open, when the last PR merges.

### Ladder threshold: step up on the 2nd findings round, on this board (decided 2026-10-25)

- **This board sets `step_up_findings = 2`; the plugin default stays 3.** `step_up_findings` is
  already a config key, so the change is a `kind: lead` story that edits `.claude/swarm/config`,
  as switching the ladder on was (config-switch-ons). The user asked for 2 on 2026-10-25; the
  round data (7 rows with a round, three step-ups) was too thin to decide either way. Changing
  the plugin default would change every ladder board on upgrade, which the "ship switched off"
  rule (docs/reference.md:328-333) reserves for a recorded exception; the v0.31.0 retro decides
  the default with data.
- **What 2 means.** The count is per rung, not per build: `findings_told` counts tells since the
  build's newest start, and a step-up is a new start (bin/lib/agents.sh:1670; reference.md:2082).
  With `sonnet,opus,fable` and N = 2 each rung gets one fix round before the build moves on; a
  PR with four findings rounds is on Fable, and one with six goes to the lead under
  `top_rung_rounds` 2.
- **The 0.28 retro reads it.** With review agents owning the loop, every round is logged with
  `--round`. There is no N = 3 cohort with round data to compare against, so the retro does not
  ask "did they converge sooner"; it reads `flow`'s `review_loops`, `reviewers` and `cost` and
  reports the share of builds that reached each rung and the lead, rounds per rung, and tokens
  per rung, against the 0.27 figures in Appendix D where they exist.
- `top_rung_rounds` stays 2.

### Top-rung cost: make it visible (decided 2026-10-25)

The ladder's top rung stays Fable at `xhigh` with `top_rung_rounds` 2; 0.28 changes nothing in
how it runs, only what is measured.

- **`flow`'s `cost` section shows tokens per ladder rung and per step-up**: for each step-up,
  what the build cost on each rung, and whether it then merged, went to the lead or failed.
- **The 0.28 retro weighs it** beside the ladder threshold above: with step-up at round 2, how
  much more ran on Fable, and whether those builds converged.
- **Considered and left for later** (user, 2026-10-25): Fable at `high` on the ladder; a usage gate that stops the ladder below Fable past a share of the weekly
  limit, which needs a reliable usage reading swarm-dev does not have (the lead's estimate
  undercounts Fable; `/usage` is the only truth).

### Less work, less noise: the 0.27 run's items (decided 2026-10-25)

From Appendix D. Codex running no tests is under Test speed above.

- **Some board-only PRs skip codex review** and merge on green CI: a conductor's story-scope
  edit, a hold, a finish, a retro file. A plan PR (epics or stories) and an HLD's agreement PR
  keep their codex pass, which with the critic and skeptics is the only review a plan gets.
  `scripts/board-only.sh` tells a board-only change apart; the plan adds the kind. 36 of 82
  merges in 0.27 were board-only.
- **A fix to the swarm's own loop ships as a patch release** soon after it merges, so the swarm
  building swarm-dev runs it. A cadence rule for the lead, who already cuts releases under
  `merge = agent`; no new machinery. Running the swarm from main was rejected: one bad merge would
  break the swarm that is running.
- **Noise goes.** A wait that times out on a busy agent logs no incident (79 in 0.27); no nudge
  goes to an agent that is working (36); briefs show the forms the guard accepts (`cd <dir> ||
  exit 1 &&`, `swarm.sh merge` alone in its call, merge text that is only mentioned through the
  Write tool or a quoted heredoc). The guard itself does not change: a merge written into a
  file that is then run is a raw merge (hooks/merge-guard.sh:43-44), and the three refusals of
  that form were the guard working.
- **One helper per duplicated piece:** the board-root path (merge, release_due, story_path,
  `board-pr open`, ci_gate), the PR contents reader (merge_read, pr_hld, release_check) and the
  herdr 32-character name cut, matched only on exact records.
- **Docs move with behaviour.** A story that changes what a user runs, sees or must do updates
  every doc that states it in the same PR, and review checks it. The release docs PR stays as
  the backstop. The first case is the `env:` line in AGENTS.md and README.md that `agent_env`

  README.md, AGENTS.md and docs/reference.md, whose prose sections are hard to name as parts,
  so they conflict more often; the builder merges main, and `flow`'s `merge_ins` counts it with
  the clash change's conflicts (Design § Clash check by part).
- **reconcile finishes a merged story** whose story file the main checkout's pull already
  removed (five skipped in 0.27).
- **The eight unfiled correctness gaps** in Appendix D are planned: each folded into

### Removing what a board sets (decided 2026-10-25)

#214 showed that checking two configs is not checking every board. The rule for anything a
board can set (a config key, a board front-matter field, a brief form the guard accepts):

- **Nothing a board sets is removed until every board the user runs has been checked for it.**
  swarm-dev has no list of those boards, so the planner asks the user to name them, and the
  story's PR quotes the check on each. A board the user forgets is the user's call, not the
  swarm's.
- **A removed key warns and loads; it never stops the board.** 0.27.1 made this true for the
  keys #214 removed. Any future removal does the same, for at least one release, before the
  name stops being recognised.
- **This is a rule, not machinery:** a line in this repo's AGENTS.md and a check in the
  removal story's **Done when**, so the swarm does not need a registry of boards.

### Clash check by part (decided 2026-10-25)

Two stories that change different parts of one file run together; git merges them, and a
builder whose PR conflicts merges main, as it already does.

- **The check compares parts.** Two stories clash only when their `touches` name the same
  `file:part`. A bare file clashes only with the same bare file, never with a part of it. Today
  a part matches by string equality (bin/lib/touches_rows.py:66) while the board's parts are
  prose (`bin/swarm.sh:CFG defaults and CONFIG_KEYS and the conduct and unblock dispatch`), so
  two planners naming one function with different words never clash; the bare-file rule was
  the net under that. Its replacement: a part is compared by its first token (the function or
  section name), and /plan-epic writes parts that start with one.
- **/plan-epic writes `file:part`.** Planners name the part a story changes, and the split
  critic flags a bare-file `touches` as a finding, so bare files become rare.
- **Backlog stories are checked as epic stories are.** The 0.27.1 case first read as a gap (two
  backlog stories naming `bin/swarm.sh:load_config` ran together) was intended behaviour: the
  child was stacked on its parent's branch and `story --strict` skips a story's own parents
  (bin/lib/touches_rows.py:92; `.swarm/conduct-backlog.report.md`). What stays is that the two
  paths apply one rule, with one test for each.
- **The cost to watch** is more merge conflicts, read from `flow`'s `merge_ins` section at the
  retro, and holds from `flow`'s `holds` section, which should fall.

## Alternatives

- **Conductor lanes** (#480, #482): several conductors per epic, each owning a share of the
  stories. Rejected: eight review rounds kept finding gaps that came from splitting stories
  between conductors (Appendix D, Design § Review in parallel).
- **One conductor that never blocks**, doing every wait in the background. Rejected: its one
  session still triages each PR in turn, so the queue shrinks but stays.
- **A read-only reviewer and a separate closer per PR**, so the role that judges the diff is
  not the one that lands it. Rejected as no safer and more machinery: the conductor today both
  judges and lands, `swarm.sh merge` is the gate either way, and a closer is one more agent per
  PR to start, watch and close.
- **A machine-wide suite cap as the test-speed fix.** Rejected as the fix: a full run with
  nothing else going still takes a median of 17.5 minutes (Appendix A). Kept as a setting, off
  by default.
- **One full local run per head instead of CI.** Rejected: CI's sharded run is about five times
  faster and is already required on `main`.
- **Generic rules in each project's brief, or as a review checklist only.** Rejected: the first
  is hand-copied and drifts; the second keeps the rules from the builder until review.
- **A retro file alone, with no `kind: lead` story.** The draft first chose it as one thing to
  check. Reversed after the reviewer's pass: `next` printing a step that needs the user makes
  hooks/lead-stop.sh hold the lead's turn, and the method's form for that is a `kind: lead`
  story. The file stays as the record the gate checks; the story is the human exit.
- **A retro before every bump, patches included.** Rejected: it ends the patch cadence that lets
  a fix to the swarm's own loop reach the swarm quickly. Minors only.
- **Fable at `high` on the ladder, or a usage gate.** Left for later by the user; the 0.28 retro
  decides with the cost data. `top_rung_rounds` 1 is not an option: the config refuses it
  (docs/reference.md:298), since at 1 every findings round after the lead lifts a hold would
  hold the story again.
- **Changing the plugin default of `step_up_findings`.** Rejected for 0.28: it reaches every
  ladder board on upgrade with no data behind it. This board sets it; the retro decides.
- **A guard on polling loops.** Rejected: it would pattern-match legitimate scripts.

## Risks and safety

- **No user step between agreement and `main`.** With `epics` and `stories` granted and
  `merge = agent` (Current state), the chain from this HLD's agreement to code on `main` has no
  user step except `kind: lead` stories and `costs: money`: /plan-hld writes epics `active`, the
  lead lands the plan PR with `merge --board`, /plan-epic files stories unasked, conductors
  build and merge, and a PR that edits `hooks/` or `.github/workflows/` is a `grants` lookup,
  not a hold. This HLD is the last gate for four releases. What keeps it safe: every epic traces
  to a Design part and every story to its epic (the critics check both); `swarm.sh merge` pins
  the head and needs every check green; the guard refuses any other merge; and the user's way
  in is `swarm.sh hold`, or flipping `merge` to `human`. The protected-path gap under
  `merge = agent` is 0.28 work (epic-guard-gaps): a hold, not a lookup, for `hooks/`,
  `.github/workflows/`, the Makefile `check` target and `.claude/`.
- **Review agents gain merge.** More agents can merge than before. Every merge still goes
  through `swarm.sh merge`, which pins the head and requires every check green, and the guard
  refuses any other merge. A review agent never edits code.
- **Touched-tests-only lets a break reach CI.** A builder that misses a covering test pushes a
  red head; CI catches it at the cost of a round trip. Test selection fails toward running more,
  and `flow`'s `ci_health` shows if red runs grow.
- **Stepping up at round 2 spends more on Fable.** One night at the top rung used about 6% of the
  week, and with one fix round per rung more builds reach Fable. The cost per rung is now
  measured and read at the retro; `top_rung_rounds` 2 still caps each PR, and the setting is
  this board's, so one line in its config turns it back.
- **Comparing parts only lets real clashes through** when a planner names the wrong part. The
  builder merges main on a conflict; `flow`'s `merge_ins` shows if conflicts grow.
- **A retro gate can block a release.** That is the point; the user runs the retro.
- **Three stages ship with no retro.** The gate arrives last, so v0.28.0 to v0.30.0 release on
  the docs gate alone, as every release before them did. The last stage's retro reads everything
  since v0.27.2, so nothing from those stages escapes it.
- **A resent brief could be sent twice** if the unsent-brief check misreads a pane. The check
  is tested against an agent that took the brief up as well as one that did not.

## Rollout

### Stages (decided 2026-10-25)

0.28 ships as a series of releases, not one. swarm-dev builds itself with the installed plugin, not
main (Non-goals; Appendix D: 0.27's fixes to the loop did not reach the conductors running them

works helps build the rest only once it is released.
Each stage is a minor release the lead cuts through `merge --release`, with the docs gate as
today and no retro until the last stage. They are minors, not patches, because the release arm
cuts a patch only when everything since the tag is a fix (commands/swarm.md:283-285), and a
stage carries features. Patches between them stay what they are today: fixes only.

| Stage | Goals | What ships | Why this order |
|---|---|---|---|
| v0.28.0 | 4, 7, 8 | Test speed, clash check by part, nothing sits unworked unseen; slow-test-files and ci-three-minutes ride here, since Design § Test speed names them | Every later build runs faster, holds less, and leaves nothing unseen |

The user agreed the principle and the grouping on 2026-10-25, and the mechanism after the
reviewer's and codex's passes: **each release holds exactly its stage.** A release is cut from
`main`, so any later-stage story merged before it would ship in it, possibly half built. So the
stages order building as well as releases. /plan-hld runs once per HLD
(commands/plan-hld.md:33-35), so all four stages' epics are planned at once, each carrying
`stage: v0.xx.0` in its front matter. Only the first stage's epics are written `active`; the later
ones are written `draft`. Once a stage's release is cut, the lead sets the next stage's epics
`active` in a board PR, under the `epics` grant, and only then do their stories build. The lead
cuts a stage's release as soon as every story of that stage's epics has merged; `next`'s `release`
line names the stage. A
`later` story (Goal 10) rides in the stage whose Design part names it, else in the last; the
plan PR that adopts it sets its `epic:` and makes it `ready`.

## Appendix C: swarm-dev's own memory, in full

The twelve files in the lead's swarm-dev memory directory, written out because the handover

**Tests and load (AGENTS.md, and 0.28 for the reaping):**
- *Tests only through make.* `env -u SWARM_PROJECT make test TESTS=tests/<file>_test.sh JOBS=4`
  for one file, without TESTS= for the suite; never `bash tests/<file>_test.sh`, and never from a
  scratch copy of main. scripts/test.sh unsets `HERDR_SOCKET_PATH` and gives each file its own
  TMPDIR and process group. On 2026-10-22 a direct events_test.sh run reached the real herdr
  socket and hung 38 minutes in `swarm.sh tidy`, which can act on real panes; direct runs with
  `SWARM_PROJECT` set wrote stub `close scope-x` lines into the real `.swarm/events.tsv`. To
  compare with main, run make in a worktree of main.
- *Unset SWARM_PROJECT; no reports over days on the real repo.* Builder shells export
  `SWARM_PROJECT`, and the dash tests then left detached CI refreshes running
  `swarm.sh flow --since <6 days ago>` against the real repo. On 2026-10-22 (PR #370) one spent
  GitHub's whole REST budget, about 4300 calls, in 14 minutes and stalled every agent. Never run
  flow, dash, outcomes or dataset against the real repo in a loop, in parallel or over days, even
  when a story's Done when names a multi-day window: run `--since <today>` once, after
  `gh api rate_limit`, and say so in the PR. After a test run, `pgrep -fl dash_slow.py` and
  `ps -eo command | grep 'swarm.sh flow --since'` must show nothing from your worktree; kill by
  PID only what names your worktree or a test temp dir.
- *Stress runs at most 4 CPUs, torn down after their check.* On 2026-10-22 an unlimited
  container plus 8 to 12 parallel test copies held all 10 cores for an hour, and three CPU
  spinners ran an hour past a load run. On 2026-10-23 a 20-run load test left four `yes` burners
  for 3 hours: in zsh, `jobs -p` did not return what the script's `wait` expected, so it waited
  on the burners forever. Write load as a bash script file that keeps PIDs from `$!`, waits on
  run PIDs only, uses self-ending burners (`perl -e 'alarm 3600; 1 while 1'`) and kills every
  process tree in an EXIT trap; `docker run --cpus 4 --rm`, `docker rm -f` after the check; size
  load to one CI shard's level; confirm with `ps` and `docker ps` that nothing is left, and say
  in the PR how the run loaded the machine.
- *codex-review orphans SLOW test files.* `swarm.sh codex-review` runs `make test` inside codex's
  sandbox. When codex exits, merge_test, dash_check_test, wait_pr_test and dash_gauges_test keep
  running with PPID 1 for minutes (2026-10-25). `kill` had no effect and a retry was refused by
  the auto-mode classifier. They end on their own and clean their temp dirs. Check
  `ps -axo pid,ppid,command | grep tests/ | awk '$2 == 1'` after a review and run the next
  `make test` with fewer JOBS until they end. 0.28: reaping (topic 3).
- *Mutation proofs in copies.* Break the fix in a copy of the worktree without `.git`
  (5 MB), run `make test TESTS=<file> JOBS=1 TEST_RUNS_LOG=` there, keep the FAIL lines, delete
  the copy; four at a time stay inside the CPU cap. On 2026-10-25 six proofs ran in one pass
  (merge_test 467 s, flow_test 183 s). Use it when a story has more than two proofs or any on a
  SLOW file, and say so in the PR.

**Review and build (0.28):**
- *Conductor review cap.* Past round 3 only a real bug (wrong behaviour, data loss, a security
  hole) sends a PR back. Start a ready story whose only blocker is a shared file in `touches`
  alongside the blocker and accept the merge conflict; still hold it if it changes the same
  function in substance. On 2026-10-18 the lead saw 12 ready stories unstarted while PRs cycled

- *A step-up that fails partway reaches the lead at once.* On 2026-10-24 findings-told-sent
  (#459) sat with no builder for about 3.5 hours because the conductor only planned to list it in

- *wait-pr stale head race.* On 2026-10-25, `git push && swarm.sh wait-pr <url>` exited 0 within a

**herdr 0.9.5 (reference for anyone changing agent state or resume), probed in throwaway named
sessions for #328 and #374:**
- On a pane `herdr agent start` opened, `report-agent --state` never changes `agent_status`;
  screen detection owns it (`herdr agent explain` shows the rule).
- The resume argv (`-- <cmd>...`) is stored as `agent_resume` in
  `~/.config/herdr[/sessions/<name>]/session.json` and wins over herdr's own
  `claude --resume <id>` on restore. `herdr api snapshot` does not show it; read session.json,
  which saves a few seconds after a change.
- `--seq` gates the stored argv: a lower seq, or an unsequenced report after sequenced ones, is
  dropped silently with rc 0. A state-only report keeps the stored argv. Every report must carry
  a seq and the argv. An apostrophe in the argv gives `invalid_resume_argv`; the first word must
  be a plain command on PATH.
- Claude Code's `/clear` fires SessionEnd (reason clear, old id), then SessionStart (source
  clear, new id); both reach plugin hooks. `claude --plugin-dir <dir>` loads a scratch plugin to
  watch them.
- `completion_seq` is a key only on a done agent; a working agent has no such key, so test with
  `in`, not `.get()`.
- `herdr agent prompt` errors are JSON on stderr, exit 1, empty stdout. `agent_blocked` is
  rejected before any input is sent; `agent_prompt_stalled` (not working within 5 s) and
  `timeout` come after sending. `agent_not_found`, `pane_not_found` and `server_unavailable` also
  occur.
- Test harness: a pane running `env -u HERDR_* herdr --session X`, driven with
  `HERDR_SOCKET_PATH=~/.config/herdr/sessions/X/herdr.sock`.

## Appendix D: the 0.27 run, what to improve, simplify or speed up

Read from `.swarm/events.tsv` and the 0.27 conductor reports (`.swarm/conduct-*.report.md`),
for v0.26.0 (2026-10-23 10:04 UTC) to v0.27.0 (2026-10-25 08:07 UTC), about 46 hours. The
conductors ran the installed 0.26.0 plugin throughout.

**What the run did:**

| Measure | Value |
|---|---|
| Merges to main (git, v0.26.0..v0.27.0) | 82, of which 36 touched only `board/` |
| Story start to merge, 43 stories | median 3.4 h, p90 8.4 h, max 12.6 h (plan-pr-grant) |
| codex-review runs | about 408; 22 failed, 4 interrupted |
| codex usage-limit incidents | 37 |
| `wait-timeout: busy` incidents | 79 |
| Nudges to an agent still working | 36 |
| "brief was not taken up" on a tell | about 29, nearly all false |
| Guard refusals | 28: 13 `cd` before `;`, 8 merge joined to another command, 4 merge fed to python3, 3 merge written to a file |
| Stall incidents | 5 |
| Findings logged | 1539 |

**Speed:**
- *Every review round costs a full local suite, and codex runs it again.* codex-review's
  `codex exec` runs `make test` in its sandbox, leaving SLOW files orphaned (Appendix C); a
  builder runs the suite before each push; CI runs it a third time. With about 408 codex runs in
  46 hours, the review loop is the largest consumer of CPU and of codex's quota (37 limit hits).
  Candidate: codex reviews the diff and never runs tests; CI is the one full run (topic 3).
- *Board PRs are nearly half the merges.* 36 of 82 merges touched only `board/`, each through
  `board-pr start`, `codex-review`, `wait-pr` and `merge --board`. Candidate: a lighter path for
  a board-only change, or batching board edits.
- *Agents poll by hand.* Two `until grep … pgrep` loops in builders hung for 2 h and 2 h 16 m,
  keeping those sessions unreachable until the conductor killed them by PID. The guard already
  refuses `gh pr checks` loops; other hand-written waits are not covered.
- *The swarm builds itself with last release's plugin.* Fixes on main (#461 step-up, #464 false
  "not taken up", #456 `--round`) did not apply to the conductors running them until 0.27
  shipped. The lead ran main's `bin/swarm.sh` by hand as a workaround, and four conductors
  logged findings with no round. Candidate: swarm-dev's own swarm runs from main, or a release
  is cut when a fix to the swarm's own loop merges. A design question for this HLD.

**Noise that hides real signals:**
- *False "not taken up".* About 29 tells, plus review-agent and step-up starts, reported a brief
  as not taken up though the agent had it (fixed by #464). The one real case, a brief unsent in
  the input box for 3h42m, was found by the lead by hand (topic 7). A signal that is nearly
  always false trains everyone to ignore it.
- *79 `wait-timeout: busy` and 36 nudges to working agents.* The conductor's waits time out
  while a builder is legitimately busy, and it nudges an agent that is still working. Neither
  carries information.
- *28 guard refusals.* Most are an agent's first try at a pattern the guard always refuses
  (`cd` then `;`), or text that mentions a merge being written to a file. Each costs a round
  trip. Candidate: briefs show the accepted form, and the guard stops matching merge text inside
  file contents.

**Simplification:**
- *One bug in several copies.* The root-board path bug sat in merge, release_due, story_path,
  `board-pr open` and ci_gate; the PR contents reader is duplicated across merge_read, pr_hld and
  release_check; the 32-character herdr cut broke close-exact-tab (#479, four rounds) and
  lifecycle's `close` for `plan-<hld>` names. Candidate: one helper each, per Appendix B's
  "fix the shared upstream cause first".
- *Docs lag behaviour.* After hld-grants, AGENTS.md:85, commands/swarm.md's release arm,
  README.md's waiting-PR row, `merge`'s usage line and reference.md's `--release` row all
  contradicted the code. docs-misstate-code is the top recurring kind (66 PRs) and the top
  declined out-of-scope kind (42). Candidate: a story that changes behaviour fixes every doc
  that states it, checked in review, not left for a release docs PR.
- *Conductor lanes added machinery faster than review closed its gaps:* #480 reached round 8
  with eleven files edited and nothing committed when it was stopped (topic 4).

**Correctness gaps the reports left for the lead** (declined out-of-scope, not filed):
- reconcile skipped five merges (flow-holds, review-loop-metrics, board-root-merge,
  tell-false-not-taken-up, test-run-log) because the main checkout had already pulled the story
  file's deletion; the conductor cleaned up by hand;
- `story --strict` let two backlog stories naming the same `bin/swarm.sh:CFG defaults` run
  together, so the clash check is too loose for backlog stories as well as too strict for bare
  files (topic 6);
- merge_grant and pr_hld re-read `headRefOid` instead of the pinned head; `release_check` reads
  the base before `gh pr merge`, so a story merged between them ships unchecked by the release
  grant;
- protected paths under a `merge` grant cover `.claude/swarm/` and `hld/` but not
  `.github/workflows/`, the Makefile `check` target or `.claude/settings.json`;
- HLD names with `.` or `_` pass `next` but are refused by board-pr, grants and finish; an HLD
  with no `## Epics` makes the plan PR fall to none silently;
- commands/hld.md and commands/epic.md step 5 open a board PR without a `board-pr start`
  worktree;
- dash puts the user's finish PR and "awaiting your merge" rows in the lead's queue;
- init never updates an existing `Board.base`.
